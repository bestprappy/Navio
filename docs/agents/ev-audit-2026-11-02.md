## Remaining confirmed issues - start here

### EV-13 / P1: power is not specific to the compatible connector

`server/mobility-and-ev-service/src/main/java/com/navio/mobilityandevservice/provider/google/GooglePlacesAdapter.java` flattens connector aggregations into connector types plus station-wide maximum kW. Its existing provider test fixture includes CCS2 150 kW and TYPE2 22 kW; the station becomes maxKw=150. `SocConstrainedRouteOptimizer.effectivePowerKw` then takes the minimum of that maximum and the vehicle's matching AC/DC limit. A TYPE2-only car with a 43 kW AC limit is therefore calculated at 43 kW instead of the fixture's 22 kW. Frontend canonical charging has the same missing evidence. This understates charge duration and may rank stops incorrectly. Station-wide availability is also not proof that a compatible plug is available.

Next action: add a failing mixed-connector provider-to-calculator regression first. Carry optional connector-specific power evidence through `EvChargerResponse`, `MobilityEvCharger`, preview DTOs, `PlannerEvChargerDto`, `BlockItem`, frontend API schemas, saved `PlaceItemEvChargerDetails` and canonical charging. Define an honest legacy fallback: do not invent a connector's kW from another connector's maximum. Preserve station maximum as a display aggregate if useful. Retain unknown availability as unknown. Account for old snapshots and rollout compatibility.

This likely needs an additive persistence change. Read `docs/agents/database-changes.md`, inspect current migrations across branches, and use the next available version. Never rewrite a merged migration. Run actual Postgres Flyway + Hibernate validation and persistence roundtrips before calling the schema work verified.

### EV-14 / P1: saved station status is discarded / assumed active

Frontend `constants/types.ts` `PlaceItemEvChargerDetails` omits operating status. Trip `TripEvOptimizationService.mapCharger` hardcodes `active` for saved stations (`TRIP_SNAPSHOT`, stale=true). Corridor searches update replaceable candidates, but locked/boundary/user-target stations can remain mandatory snapshots with obsolete operating state. Blocking new known-closed additions (EV-11) does not fix an existing charger that later closes.

Next action: reproduce a saved locked charger whose refreshed provider state is closed. Preserve status/provenance/timestamp in snapshots and design bounded revalidation of all charging stops used by preview/apply, including mandatory and previous/following-day charging evidence. On provider failure, do not present old evidence as freshly verified. Preserve user stop identity, order, lock and explicit target; a closed pinned stop should not silently be moved or deleted. Coordinate this contract/schema work with EV-13.
