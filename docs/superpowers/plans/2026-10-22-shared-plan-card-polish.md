# Shared Plans card polish implementation plan

User scope: compact premium image-led informative Shared Plan cards; matching functioning covers; at least6 initial Trending plans when6 exist, Load more; views/rating/copies on cards. Clarification: rating remains Not rated yet (no voting feature); card counts all successful copies; detail shows total copies and distinct copiers. Do not touch deferred Places articles, Guides, Admin or sidebar.

1. Add failing frontend regressions for visible day/stop counts, views/copies/unrated state and image reference parsing; confirm red. Add/backend regression for successful-copy record only after save, summary cover reference and metrics, detail aggregates. Preserve privacy of unlisted snapshots and author identities.
2. Backend: additive V21 migration (verify all branches first) for copy-event ledger, backfill recoverable existing imported trips via destination_id shared-plan:<publication UUID>. No copied-trip FK so deleting a copy does not erase its historical event; publication deletion cascades. Repository batches counts and distinct users for page publication IDs. Record event within successful copy transaction. DTO exposes counts and sanitized existing stop reference for cover lookup; detail engagement only for listed plans. Existing old DTO constructors remain compatible. Validate fresh and upgrade migrations plus count semantics on disposable PostgreSQL.
3. Frontend: compound SharedPlanCard, separate lazy PlanCover and reusable engagement row. Stored valid cover first; if absent/broken, resolve live photo of a published public itinerary stop via existing Places reader API. Keep credits/source links, no unrelated stock photograph. Query only visible/near-visible cards, dedup by place identity, bounded retries and graceful fallback; no extra snapshot/public-detail requests that inflate view counts. Use explicit unavailable counts if older backend lacks fields.
4. Compact responsive tile/row/planner variants: short cover,2-line title, location, day/stop counts, highlights, author and3 statistics. Keep keyboard/stretched-link semantics with independent photo-credit links. Trending6 first then6 more via existing infinite query with correct SSR/client page size and retry/error/loading states, no extra fabricated plans.
5. Add total/distinct copy statistics to listed shared-plan detail using its existing response schema. Full frontend/backend tests, TypeScript, scoped lint, build, PostgreSQL startup/upgrade checks; independent review. No source commit/push/deploy requested. Preserve existing dirty client work; docs-only session commit at end per AGENTS.

Decisions: views are existing public read counts, not unique people. Copies count successful imports, not actual travel. Historical backfill can recover only copies still identifiable in stored trips; never invent deleted historical counts. Publication stats survive republishing the same plan; view counter retains existing link-reset semantics. Ratings deliberately unrated per user. Work in existing checkout to preserve current unfinished changes. No new rating endpoints or rating schema.
